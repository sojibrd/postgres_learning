# নিয়ম — Postgres, rule ধরে প্রথম পরিচয়

*৩৫ দিন · ৩১টা rule আর ৪টা ⚑ · দিনে একটা, ১০′*

## লক্ষ্য

> **৩৫ দিনে Postgres-এর ৩১টা best practice-এর প্রতিটায় Correct SQL-টা পড়ার পরে বন্ধ করে নিজে লিখতে পারা, আর "কেন" ইংরেজিতে নিজের কথায় বলতে পারা — ঝালাইসহ।**

এটা SQL গোড়া থেকে শেখানোর সাইট নয়, আবার জানা জিনিসের "কেন" ঝালানোরও নয়: এখানে প্রতিটা rule প্রথম পরিচয়। তাই না দেখে ঠিকটা লেখা নয় — ক্রমটা আন্দাজ → পড়া → বন্ধ করে লেখা। 🧠 (Test yourself · Active vs Passive learning)

এটা "শুধু পরিচয়" — ১৮০ দিনের plan-এর backend পথ বদলায় না। হাতে-কলমের database কাজ (আসল data, আসল migration) এখনো ২০২৮-এর শেষে, `leave_management`-এ (`brainstorming/fullstack.md`)।

## সত্যের উৎস

এই সাইট Postgres নিয়ে নিজের কোনো rule বা ব্যাখ্যা যোগ করে না — প্রতিটা দিনের SQL আর ব্যাখ্যা rule-এর ফাইল থেকেই।

1. `guide/` — `supabase-postgres-best-practices` skill-এর ৩১টা rule ফাইল, হুবহু ইংরেজিতে। লেখক, সংস্করণ আর লাইসেন্স `guide/README.md`-এ; সেকশনের নাম আর ক্রম `guide/_sections.md`-এ।
2. `docs/` — এই plan: নিয়ম আর ৪টা ব্লক।
3. ⚑ দিনের প্রশ্ন — ব্লক ২-এরটা `brainstorming/system-design.md` থেকে ("SQL না NoSQL, index কেন লাগে"); বাকি তিনটায় ব্লকের rule-ই প্রশ্ন।

## উৎসটা কী, কী নয়

- **Supabase-এর লেখা, শুধু Postgres।** ৩১টা rule-এর সবগুলোই PostgreSQL-এর; NoSQL নেই। rule-এর মূল লেখায় Supabase-এর নাম নেই — আছে শুধু ১৩টা Reference লিংকে।
- **SQL-এর গোড়া ধরে নেওয়া।** rule-গুলো ধরে নেয় `SELECT`, `JOIN`, `CREATE TABLE`, `CREATE INDEX` চেনা। এই সাইট ওগুলো শেখায় না; আটকালে যাওয়ার জায়গা প্রতিটা rule-এর শেষের Reference লিংক।
- **migration আলাদা সেকশন নয়।** শুধু দুটো rule-এ আসে — "Add Constraints Safely in Migrations" (দিন ০০১) আর "Use Lowercase Identifiers for Compatibility"।
- **কোনো Postgres version-এর সাথে মেলানো হয়নি।**

### Reference লিংক — ২০২৬-১০-১২-এর পরীক্ষা

## কীভাবে পড়বেন

- ৩৫ দিন, ৪টা ব্লক — শেখার ক্রমে: Schema → Query আর index → Security আর locking → Data আর connection। উৎসের সেকশন ভাঙা হয়নি, শুধু ক্রম বদলেছে; সেকশনের ভেতরে rule ফাইলনামের ক্রমে, কারণ উৎস নিজে কোনো ক্রম লেখেনি।
- প্রতিটা দিনে একটা rule, একটা `- [ ]` কাজ, আর শেষে **দিন শেষে** প্রশ্ন — হ্যাঁ/না। ব্লকের শেষ দিনটা ⚑।
- `১০′` = মিনিট।
- কাজের নিচে rule-এর **Incorrect SQL**, আর "আগে আন্দাজ → Correct আর ব্যাখ্যা" লিংক। লিংকটা টিকের আগেই থাকে, কারণ পড়াটা কাজেরই অংশ — কিন্তু আন্দাজের পরে। 🧠 (Test yourself)
- `impact` chip = উৎসে rule-টার গুরুত্ব, CRITICAL থেকে LOW।
- 🧠 (নাম) = কাজটা `learning_to_learn`-এর কোন নীতি থেকে; chip চাপলে এক লাইনে কেন।
- 🔁 = এই কাজ শেষ করার দিন থেকে **১, ৩, ৭, ২১ দিন পরে** না দেখে আবার। তারিখ সাইট নিজে হিসাব করে।
- ⚑ = মাইলফলক। নির্ধারিত দিনে না হলে শেষ না হওয়া পর্যন্ত হোমে থাকে।

## "আজ" মানে ক্যালেন্ডারের আজ

ফাইলে তারিখ নেই, শুধু দিনের নম্বর। প্রথমবার সাইট খুললে শুরুর তারিখ জিজ্ঞেস করে। তারপর থেকে দিন = শুরু থেকে কত দিন।

- **plan পেছায় না।** কাল বাদ পড়লে আজ আজকের rule, দুটো নয়।
- **বাদ পড়া rule ফেরে না** — গাইডে থাকে, দিন ০৩৫-এর পরে ধরতে পারেন।
- **ঘুম কেটে পূরণ নয়।** 🧠 (The science of sleep)

## কখন বসবেন ⏳

এই সাইটের দিনের ১০′ ১৮০ দিনের plan-এর সপ্তাহে ৭ ঘণ্টার **ভেতরে, নাকি বাইরে** — ⏳ আপনার উত্তর বাকি। `emberjs_learning`, `nextjs_learning` আর `nestjs_learning`-এর সাথে একসাথে চলবে, নাকি পরপর — সেটাও ⏳। উত্তর না আসা পর্যন্ত plan-এর কোনো ঘর থেকে সময় কাটা হয়নি, আর শুরুর তারিখের কোনো প্রস্তাব নেই।

## বসা — ১০′

১০′ একটা আন্দাজ, মাপা নয় — rule-গুলো ছোট (৪০ থেকে ৮০ লাইন)। সময়ে না ধরলে প্রথম Incorrect–Correct জোড়াটুকুই আজকের কাজ।

1. **টাইমার ১০′।** 🧠 (Have an endpoint)
2. **Incorrect SQL-টা পড়ুন, আর খাতায় এক লাইনে আন্দাজ লিখুন** — কী ভুল। না চিনলেও একটা আন্দাজ; ফাঁকা নয়। 🧠 (Test yourself)
3. **গাইড খুলে Correct আর ব্যাখ্যা পড়ুন।** কোনো শব্দ না চিনলে rule-এর শেষের Reference লিংক — শুধু ঐ একটা পাতা।
4. **গাইড বন্ধ করে Correct SQL-টা নিজে লিখুন** — editor-এ বা কাগজে; চালাতে হবে না। 🧠 (Active vs Passive learning)
5. **"কেন" ইংরেজিতে, ২–৩ বাক্যে, জোরে।** 🧠 (Feynman technique)
6. **টিক দিন**, তারপর নিজের লেখা গাইডের সাথে মেলান। যেটুকু মেলেনি, সেটাই কালকের ঝালাইয়ের জায়গা। 🧠 (The science of feedback)

সাইটে নোটের ঘর নেই, ইচ্ছা করেই; আন্দাজটা খাতায়।

## ঝালাই

- 🔁 কাজে টিক দিলে ঐ **আসল তারিখ** থেকে ১ → ৩ → ৭ → ২১ দিন। 🧠 (Spaced repetition revisited)
- **ঝালাইয়ের বসা:** rule-এর নাম দেখে, গাইড না খুলে — "কেন" এক লাইনে, ইংরেজিতে, জোরে। প্রথম পরিচয়ের rule-এ আসল অনুশীলন এখানেই।
- দুটো উত্তর: **মনে ছিল** (পরের ধাপে) বা **আটকে গেছি** (আবার ১ দিনে)। আটকে যাওয়া শাস্তি নয়, তথ্য।
- ২১ দিনের ধাপ পার হলে ঝালাই শেষ — ওটা এখন স্থির।

## ⚑ দিন — মুখে ২ মিনিট

প্রতিটা ব্লকের শেষ দিনে একটা প্রশ্ন: গাইড না খুলে, ইংরেজিতে, জোরে, ২ মিনিটে।

| দিন | ব্লক | প্রশ্ন |
|---|---|---|
| ০০৭ | Schema | ব্লকের তিনটা rule-এর "কেন" |
| ০১৬ | Query আর index | SQL না NoSQL, আর index কেন লাগে — দ্বিতীয় অংশে ব্লকের rule থেকে অন্তত দুটো উদাহরণ; প্রথম অংশ আপনার নিজের উত্তর |
| ০২৪ | Security আর locking | ব্লকের তিনটা rule — দুই সেকশনের প্রতিটা থেকে অন্তত একটা |
| ০৩৫ | Data আর connection | ব্লকের তিনটা rule — Data access আর Connection থেকে অন্তত একটা করে |

## গাইডের পাতা

"গাইড" পাতায় ৩১টা rule, উৎসের ৮টা সেকশন ধরে; প্রতিটার পাশে কোন দিনে আসে। rule-এর পাতায় Incorrect SQL খোলা আর পুরো rule ভাঁজ করা — আন্দাজের পরে নিজে খুলবেন; plan-এ ঐ কাজে টিক থাকলে ভাঁজ নিজে খোলে। পাতাগুলো রেফারেন্স; রোজ শুরু "আজ" থেকে। 🧠 (Create a roadmap)
